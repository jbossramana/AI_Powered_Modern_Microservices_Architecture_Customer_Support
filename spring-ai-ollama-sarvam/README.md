# Spring AI + Ollama + Sarvam (Local Model)

A small Java 21 / Maven / Spring Boot project that calls a model through Ollama using Spring AI.

## Important model and API-key distinction

- **Local Ollama inference:** does not require a Sarvam cloud API key.
- **Sarvam's hosted API:** requires a Sarvam API key and uses a different Spring AI integration path.
- This project defaults to the community Ollama model name `frob/sarvam`. It is **not** Sarvam's hosted `sarvam-105b` API model. Community packaging, availability, licence, and hardware requirements can change. Verify the exact model on the Ollama library before downloading.
- If `frob/sarvam` is unavailable in your Ollama installation, set `OLLAMA_MODEL` to the exact model name you successfully installed. This project cannot make an unavailable model work simply by changing the name.

## Architecture

`curl / client -> Spring Boot REST API -> Spring AI ChatClient -> Ollama HTTP API -> local model`

## Requirements

- JDK 21
- Maven 3.9+
- Ollama for Windows: https://ollama.com/download
- Enough free disk/RAM for the selected model. A model package around 20 GB may need substantial additional memory to run.

## 1. Verify Java, Maven, and Ollama

Open **Windows Command Prompt**:

```bat
java -version
mvn -version
ollama --version
```

Ensure Java reports version 21.

## 2. Download and test the community Sarvam model

```bat
ollama pull frob/sarvam
ollama list
ollama run frob/sarvam
```

At the model prompt, try:

```text
Explain microservices architecture in simple Telugu.
```

Exit the interactive model with `/bye`.

If the pull command fails, check the current Ollama library listing and use a model name that is actually available to you. The `frob/sarvam` name is a community package, not a guarantee of an official Sarvam release.

## 3. Run the Spring Boot application

From the directory containing `pom.xml`:

```bat
mvn clean test
mvn spring-boot:run
```

The API starts on `http://localhost:8080`. Keep Ollama running in the background.

If your Ollama model name differs, start the application like this in Command Prompt:

```bat
set OLLAMA_MODEL=your-exact-ollama-model-name
mvn spring-boot:run
```

The default Ollama base URL is `http://localhost:11434`. Override it if necessary:

```bat
set OLLAMA_BASE_URL=http://localhost:11434
```

## 4. Test endpoints with Windows curl.exe

### Health check

```bat
curl.exe -i http://localhost:8080/api/health
```

Expected shape:

```json
{"status":"UP","application":"spring-ai-ollama-sarvam"}
```

This checks the Spring Boot application only; it does not guarantee that Ollama or the model is ready.

### GET request

```bat
curl.exe -G "http://localhost:8080/api/ask" --data-urlencode "question=Explain Spring Boot in Telugu"
```

### POST request

```bat
curl.exe -X POST "http://localhost:8080/api/chat" -H "Content-Type: application/json" -d "{\"question\":\"Explain microservices in simple Telugu\"}"
```

Example response shape:

```json
{
  "model": "frob/sarvam",
  "answer": "..."
}
```

The answer text is generated by the model and will vary.

## 6. Troubleshooting

### `model not found`
Run `ollama list` and confirm the exact name. Pull the model first, then set `OLLAMA_MODEL` to that exact name.

### Connection refused on port 11434
Ensure Ollama is installed and running. Test with:

```bat
curl.exe http://localhost:11434/api/tags
```

### Slow response or out-of-memory errors
Large models need substantial RAM/VRAM. Try a smaller compatible model or a quantized variant if available.

### Maven dependency resolution failure
This project is configured for Spring Boot **4.1.0** and Spring AI **2.0.0** as requested. If Maven reports that a version cannot be resolved from your configured repositories, verify release availability and repository configuration before changing versions.
